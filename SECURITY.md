# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |

## Reporting a Vulnerability

Если вы нашли уязвимость, пожалуйста, **не открывайте публичный issue**.

Используйте **GitHub Security Advisories**:

https://github.com/daniil-avdeenko/FastApi-Finance-Agent/security/advisories/new

В сообщении укажите:

- версию или коммит, где воспроизводится уязвимость;
- пошаговый сценарий воспроизведения;
- ожидаемое и фактическое поведение;
- потенциальное влияние (утечка данных, эскалация привилегий, DoS и т.п.).

## Response SLA

- Подтверждение получения: **7 дней**.
- Первичная оценка: **14 дней**.
- Исправление (если применимо): **30 дней** с момента подтверждения.
- Публичное раскрытие деталей — по согласованию, после выхода исправления.

## Scope

**В скоупе:**

- FastAPI-приложение (https://agent.projectfin.com.ru) — обработка входящих HTTP-запросов, интеграция с LLM, Telegram webhook.
- Telegram-бот — авторизация webhook, rate limit, обработка пользовательских сообщений.
- Взаимодействие с публичным API основного проекта (`/api/v1/*`).
- Инфраструктура развёртывания — конфигурация Nginx, TLS, Docker-сети.

**Вне скоупа:**

- Уязвимости в сторонних сервисах (GigaChat, OpenRouter, Telegram Bot API, проект `project-finance`) — сообщайте в upstream.
- Уязвимости в зависимостях — сообщайте в соответствующие репозитории.
- Social engineering, фишинг, физический доступ.

## Known Limitations

- **`POST /chat` — опциональная авторизация через `X-API-Key`.** Если `API_KEY` задан в env, endpoint требует совпадающий header. Если пуст — endpoint открыт (для локальной разработки и публичного демо). Для production **рекомендуется** задать `API_KEY`. Rate limit на этом эндпоинте не настроен — rate limit работает только на `user_id` в Telegram-боте.
- **`GIGACHAT_VERIFY_SSL=false` в production** — временный обход проверки сертификатов GigaChat; для полной проверки нужны сертификаты Минцифры (Russian Trusted Sub CA), установка на сервер — в бэклоге. Влияет только на исходящие запросы к `api.giga.chat`, не на входящие. Риск MITM ограничен сетевым периметром между NL-сервером и GigaChat; данные — демонстрационные.
- **Rate limit на Telegram — Redis-backed, с fallback на memory.** Если Redis недоступен на старте — middleware работает с in-memory `deque` (лимит на процесс, не на пользователя). При падении Redis в рантайме — та же деградация до восстановления. Бот остаётся доступным, но лимит становится per-worker.
- **HSTS отсутствует** — заголовок `Strict-Transport-Security` не выставлен. Планируется добавить отдельно (в бэклоге).
- **CORS не настроен** — API не предназначен для использования из браузера. Cross-origin запросы не разрешены.
